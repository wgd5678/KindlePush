# Kindle推送助手 - 软件需求规格说明书 (SRS)


## 1. 项目概述

### 1.1 项目背景
用户需要将电脑本地的PDF、EPUB等文档，经过格式转换后推送到个人Kindle设备，并支持转换后文件的本地下载备份。

### 1.2 项目目标
开发一款Windows桌面应用程序，核心功能为：
- 支持多种文档格式（PDF、EPUB、DOCX等）添加与管理
- 利用亚马逊官方服务完成格式转换（PDF → KFX）
- 提供三种推送方式：邮件推送、HTTP API推送、USB传输
- 提供转换后文件本地下载功能
- 打包为单个 `.exe` 文件，方便分发

### 1.3 目标用户
- Kindle电子书阅读器用户
- 需要批量处理电子书的技术爱好者
- 习惯桌面端操作而非网页操作的用户


## 2. 技术栈

| 层级 | 技术选型 | 版本 | 说明 |
|------|---------|------|------|
| 编程语言 | Python | 3.10+ | 开发效率高，库生态丰富 |

#### 3.3.1 设计原则
**不在本地进行格式转换**，而是将原始文件通过亚马逊官方推送服务进行云端转换。

#### 3.3.2 转换原理

| 推送方式 | 转换触发机制 | 输出格式 |
|---------|-------------|---------|
| 邮件推送 | 邮件主题设置为 `Convert` | KFX |
| HTTP API推送 | API内部自动转换 | KFX |
| USB传输 | 不转换，直接复制原始文件 | 保持原格式 |

```
用户添加文件 → 选择推送方式 → 调用推送接口 → 亚马逊云端自动转换 → 推送到Kindle
```

#### 3.4.2 方式二：HTTP API推送

**适用场景**：文件 > 50MB，追求更佳体验

**技术方案**：使用 `stkclient` Python库

**核心优势**：
- 突破50MB文件大小限制
- 无需配置SMTP邮箱
- OAuth2标准授权

**实现流程**：

```
1. 用户点击"API授权"
   ↓
2. 打开浏览器，跳转亚马逊登录页
   ↓
3. 用户登录并授权
   ↓
4. 获取OAuth令牌，创建Client
   ↓
5. 保存Client状态（避免重复授权）
   ↓
6. 获取用户Kindle设备列表
   ↓
7. 用户选择目标设备
   ↓
8. 调用send_file()推送文件
```

**代码接口**：

```python
class KindleAPIClient:
    def __init__(self):
        self.client = None
        self.devices = []
    
    def authorize(self) -> str:
        """发起OAuth授权，返回登录URL"""
        auth = stkclient.OAuth2()
        return auth.get_signin_url()
    
    def finish_authorization(self, redirect_url: str) -> bool:
        """完成授权，创建Client"""
        auth = stkclient.OAuth2()
        self.client = auth.create_client(redirect_url)
        return self.client is not None
    
    def get_devices(self) -> list:
        """获取用户Kindle设备列表"""
        devices = self.client.get_owned_devices()
        return devices.owned_devices
    
    def send_file(self, file_path: str, device_serial: str, title: str = None) -> bool:
        """推送文件到指定设备"""
        if not title:
            title = os.path.basename(file_path)
        self.client.send_file(
            filepath=file_path,
            destinations=[device_serial],
            title=title
        )
        return True
    
    def save_state(self, path: str):
        """保存Client状态"""
        with open(path, 'w') as f:
            self.client.dump(f)
    
    def load_state(self, path: str) -> bool:
        """加载Client状态"""
        try:
            with open(path, 'r') as f:
                self.client = stkclient.Client.load(f)
            return True
        except:
            return False
```

#### 3.4.3 方式三：USB传输

**适用场景**：无网络环境、超大文件、用户偏好有线传输

**功能点**：

| 功能点 | 说明 |
|--------|------|
| 设备检测 | 自动检测Kindle盘符（通过VID/PID识别） |
| 文件复制 | 将文件复制到 `Kindle盘:\documents\` 目录 |
| 进度显示 | 显示复制进度 |
| 无大小限制 | 仅受存储空间限制 |

**实现方案**：

```python
import psutil
import shutil

def detect_kindle() -> str:
    """
    检测Kindle设备盘符
    :return: 盘符路径，如 'E:\\'
    """
    # 方法1：通过Volume Label识别（通常为"Kindle"）
    for partition in psutil.disk_partitions():
        if 'removable' in partition.opts and 'Kindle' in partition.device:
            return partition.mountpoint
    
    # 方法2：通过USB设备VID/PID识别
    # Kindle的VID通常为 0x1949
    # 需要额外使用pyusb或win32api
    
    return None

def push_by_usb(file_path: str, kindle_path: str) -> bool:
    """
    通过USB推送文件
    :param file_path: 源文件路径
    :param kindle_path: Kindle盘符
    """
    dest = os.path.join(kindle_path, 'documents', os.path.basename(file_path))
    shutil.copy2(file_path, dest)
    return True
```

### 5.2 异常处理

| 异常场景 | 处理策略 | 用户提示 |
|---------|---------|---------|
| 文件不存在 | 跳过该文件，记录错误 | "文件不存在: xxx" |
| 文件 > 50MB (邮件推送) | 阻止推送，建议改用API | "文件超过50MB，请使用API推送方式" |
| SMTP连接失败 | 重试3次，均失败则报错 | "邮件服务器连接失败，请检查网络和配置" |
| SMTP认证失败 | 报错 | "邮箱认证失败，请检查密码/授权码" |
| API授权过期 | 引导用户重新授权 | "授权已过期，请重新授权" |
| API推送失败 | 记录错误详情 | "API推送失败: xxx" |
| Kindle未连接 (USB) | 报错 | "未检测到Kindle设备，请通过USB连接" |
| 磁盘空间不足 (USB) | 报错 | "Kindle磁盘空间不足" |

## 9. 风险与应对

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|---------|
| stkclient库更新或不兼容 | API推送功能失效 | 中 | 定期检查库更新；准备备用方案（自行实现API） |
| 亚马逊API变更 | API推送功能失效 | 低 | 关注社区动态；用户可回退到邮件推送 |
| 邮箱服务商限制 | 邮件推送失败 | 中 | 支持主流邮箱（Gmail/QQ/163/Outlook）；提供详细配置指引 |
| PyInstaller打包兼容性 | 无法生成exe | 低 | 使用虚拟环境；提前测试打包流程 |
| 用户操作不当 | 功能使用异常 | 高 | 提供完善的操作提示和错误信息 |
